# Persona

`docs/product/personas/<slug>.md`, one per persona, such as `client-owner.md`.

A persona is a reusable description of a type of person who uses the product. It
says who they are, not what they came to do. The goal, the scenario, and the
test account belong to each run, so the same persona works for any flow. The
`personas` skill finds, chooses, and creates them.

## Layout

```markdown
# <Name>, <role>

## Who

<Their job, and why they use this product, in a sentence or two.>

## Knows

<Domain knowledge, familiarity with this product, technical skill.>

## Context

<Device, how often they do this, time pressure, interruptions.>

## Expects

<The words they use, the tools they already know, how they think this kind of
work goes.>

## Cares about

<What makes them trust it, and what would make them give up.>

## Based on

<The user's answers, project docs, or research. Say what's assumed.>
```

## Sections

All are required. Names are invented.
